🔗 What Is a Microservice Architecture?

A microservice architecture structures an application as a set of services with distinct responsibilities. Services communicate through defined interfaces, often using HTTP APIs.

Each service can focus on a particular task, such as serving a user interface, processing application data, or storing information in a database.

Containers make services easier to package and run consistently. However, using Docker does not automatically make an application a microservice architecture: the responsibilities and communication between services matter too.

The Application Architecture

Docker Learning Hub has three services. Each has a different responsibility, and together they provide a working application.

1. Web application

The web service uses Flask and Gunicorn to serve the website. It renders HTML pages and sends HTTP requests to the API.

2. API service

The API receives requests to retrieve or create notes. It validates the submitted data and performs database operations.

3. PostgreSQL database

PostgreSQL stores the notes. The API connects to the database using the database service name and credentials supplied through environment variables.

The web service is published on the host at localhost:5001. The API and database do not need published host ports for the other containers to reach them over the Compose network.

What Is an API?

An Application Programming Interface (API) defines how software components can interact. A web API commonly uses HTTP methods to perform operations on resources.

GET — retrieve data

The API supports GET /notes, which returns the notes stored in PostgreSQL.

POST — create data

The API supports POST /notes, which accepts a note title and content in JSON format, validates the input, and stores the new note.

Health checks

The API's /health endpoint checks whether it can communicate with the database. The web application's /health endpoint checks the API and reports its status.

Why Separate the Services?

  • Separation of responsibilities: The web interface does not need to manage SQL queries itself.
  • Maintainability: The API and web interface can be developed separately.
  • Reproducibility: Docker packages each service with its required dependencies.
  • Persistence: PostgreSQL stores application data in a named volume.

This is a small educational example of a multi-service architecture. It demonstrates separation of responsibilities without the operational complexity of a large production system.
